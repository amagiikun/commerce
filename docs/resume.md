# 简历项目经历素材

## 项目名称

Smart Commerce Admin（电商品牌运营后台）

## 项目定位

面向电商品牌运营场景的中后台项目，覆盖登录鉴权、数据看板、商品管理、订单管理、营销活动管理等核心业务链路，完成了从前端页面、接口联调到数据库持久化的完整闭环。

## 技术栈

- 前端：`Vue 3`、`TypeScript`、`Vite`、`Vue Router`、`Pinia`、`Element Plus`、`ECharts`、`Axios`
- 后端：`Node.js`、`Express`、`Prisma`、`MySQL`、`JWT`、`bcryptjs`
- 测试与工程化：`Vitest`、`Supertest`、`jsdom`

## 一句话版本

基于 `Vue 3 + TypeScript + Express + Prisma + MySQL` 独立搭建电商品牌运营后台，完成 RBAC 鉴权、数据看板、商品/订单/活动管理、前后端联调与数据库持久化，并通过测试与文档沉淀提升项目可维护性。

## 简历项目经历版（推荐直接使用）

### 版本一：通用版

负责电商品牌运营后台项目的全栈开发，基于 `Vue 3 + TypeScript + Vite + Express + Prisma + MySQL` 搭建前后端分离架构，完成登录鉴权、角色权限控制、数据看板、商品管理、订单管理、营销活动管理等核心模块，并实现从本地 Mock 向真实后端服务的平滑迁移。

- 基于 `Vue Router + Pinia` 设计前端权限体系，支持 `admin / operator / marketing` 三类角色的菜单与路由动态裁剪，提升系统可用性与业务隔离能力
- 封装统一请求层与登录态管理能力，实现 `token` 注入、401 失效清理、统一异常处理，降低页面重复逻辑与联调成本
- 搭建品牌运营数据看板，结合 `ECharts` 实现 GMV、订单趋势、转化率、退款率、热销商品、活动表现等经营指标可视化
- 基于 `Express + Prisma + MySQL` 设计商品、订单、订单明细、活动、用户等核心数据模型，落地商品筛选分页、订单详情、活动详情、商品编辑持久化等业务能力
- 实现 `JWT + bcryptjs` 认证链路，并通过仓储抽象同时支持 Prisma 持久化仓储与 In-Memory 测试仓储，提升系统可测试性与可维护性
- 使用 `Vitest + Supertest` 覆盖权限、登录态、查询参数、接口鉴权、筛选分页、详情查询、商品更新、看板聚合等核心场景，并补充架构/API/开发文档，增强项目工程化成熟度

### 版本二：偏前端版

负责电商品牌运营后台前端架构与核心业务页面开发，基于 `Vue 3 + TypeScript + Vite + Pinia + Element Plus` 完成登录鉴权、品牌运营驾驶舱、商品管理、订单管理、营销活动等模块建设，并推动前端从本地 Mock 向真实后端接口迁移。

- 设计并实现基于角色的前端权限控制方案，支持 3 类角色的动态菜单与路由访问控制
- 封装 Axios 请求层和会话管理能力，实现鉴权头注入、401 自动清理与统一错误提示
- 抽象 `PageHero`、指标卡、筛选栏、详情抽屉/弹窗等高复用业务组件，提升中后台页面开发效率
- 使用 `ECharts` 搭建多维经营分析看板，展示 GMV、订单量、热销商品、活动表现等关键指标
- 为权限过滤、登录态存储、格式化工具、核心页面结构与交互补充单元测试，提升关键功能稳定性

### 版本三：偏后端版

负责电商品牌运营后台后端服务开发，基于 `Node.js + Express + Prisma + MySQL` 构建 RESTful API，覆盖登录鉴权、商品管理、订单管理、活动管理、数据看板等核心业务，并通过仓储解耦和接口测试提升系统可维护性。

- 设计并实现 `JWT + bcryptjs` 认证体系，完成登录签发、鉴权中间件校验与统一异常返回
- 抽象统一数据访问接口，分别落地 Prisma 持久化仓储与 In-Memory 测试仓储，实现业务层与存储层解耦
- 基于订单、商品、活动等数据实现看板聚合计算，输出 GMV、订单趋势、转化率、退款率、热销商品 TOP、活动投放摘要等指标
- 支持商品/订单/活动的关键词过滤、状态筛选、分页查询与详情读取，形成完整中后台 API 能力
- 使用 `Vitest + Supertest` 覆盖登录、鉴权、筛选分页、详情查询、商品更新和看板聚合等主流程，降低对真实数据库环境的依赖

## STAR 面试表述版

### STAR 版本一

- **S（背景）**：原项目最初以纯前端 + 本地 Mock 为主，缺少真实接口、数据持久化与完整联调链路，项目展示深度有限。
- **T（任务）**：将项目升级为可用于简历展示的完整电商运营后台，既能体现前端页面能力，也能体现后端接口、数据库设计和工程化能力。
- **A（行动）**：我基于 `Vue 3 + Express + Prisma + MySQL` 重构整体架构，统一 `/api` 接口前缀与返回结构，设计 JWT 鉴权链路、RBAC 权限模型、商品/订单/活动数据模型与看板聚合接口，并补充测试与开发文档。
- **R（结果）**：最终项目形成从登录鉴权、业务管理到数据分析看板的完整业务闭环，支持前后端独立启动、数据库初始化、接口联调和核心场景自动化测试，项目成熟度和简历说服力显著提升。

### STAR 版本二

- **S（背景）**：中后台项目常见问题是页面多但复用弱、接口层混乱、联调成本高，导致项目可维护性和展示效果都较差。
- **T（任务）**：在保证业务完整度的前提下，提升项目的架构清晰度、组件复用度、测试稳定性和面试可讲述性。
- **A（行动）**：我按“页面层、组件层、请求层、权限层、数据层”进行拆分，封装通用请求与登录态逻辑，抽象复用组件，后端使用仓储模式隔离数据库实现，同时引入 `Vitest + Supertest` 覆盖核心链路。
- **R（结果）**：项目既能展示完整业务场景，也具备较好的工程化质量，面试中可以从前端交互、后端架构、数据库设计、测试策略多个维度展开讲解。
